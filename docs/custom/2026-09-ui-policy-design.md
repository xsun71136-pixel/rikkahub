# R2：重试 / 多 Key 体验重构与 KEY 管理策略设计（先设计后实施）

## 1 基线与诊断
远端 88cc9ff3258d，源码 df99692；工作区已备份。旧重试 UI 为一长串滑条、无等待预览，保存按钮随正文滚动；Key 卡将六种操作挤进一行（38dp图标触点）、列表固定480dp、不支持搜索筛选、测试结果仅Toast；健康规则硬编码24h与1~30min。

## 2 统一交互
采用 Material3 全尺寸 Dialog（大屏最大840dp），固定标题/关闭与底部保存栏，正文独立滚动，支持IME/系统栏；保持动态配色、明暗主题。新增共享 PolicyUi：分组卡、说明、全行开关、数值滑条、状态摘要。编辑类界面草稿保存，返回有未保存确认；即时 Key 管理明确标注即时保存，不混用保存语义。

## 3 自动重试
推荐/快速/耐心三种完整预设（预设选中按实际配置对比，编辑后为自定义），总开关、有限次数、等待序列与总等待预览（关闭抖动计算、提示实际±20%）；分基本/规则两页，基础参数组与安全组分离。保留自定义HTTP状态码和关键词；状态码范围400..599，错误显示而不是静默忽略。部分响应重放需二次确认。保存/重置固定底栏；草稿用rememberSaveable序列化防旋转丢失。

## 4 多 Key 管理
固定标题关闭、滚动单一LazyColumn覆盖统计/策略/搜索/操作/列表，避免短屏裁切。统计可用/人工关闭/自动停用/冷却；搜索别名或Key片段，状态筛选不改变真实条目序号；两行卡（标题+开关，掩码+状态）与独立操作行，48dp触点。测试显示持久结果/耗时，超时边界，离开取消；取消或超时不处罚Key；测试成功才恢复原健康记录（不再测试前无条件恢复）。编辑重复Key明确拒绝，不静默丢数据；导入预览新增/重复计数；批量启用/关闭/恢复需确认且作用范围明确为整个供应商。禁止自动读取剪贴板。

## 5 网络→KEY管理
全局配置 KeyManagementPolicy（ai层可序列化，旧备份默认兼容），适用于开启多Key的OpenAI/Google/Claude，不管理Vertex服务账号。分别配置 INVALID、QUOTA、429动作：不处理、冷却、停用；停用支持到期重试或手动恢复，默认维持24h；冷却基数/上限/指数倍率；全局总开关；Key故障自动切换开关、最大额外尝试及等待。关闭策略不删除旧记录但不阻止使用，重新开启旧未过期记录仍生效；策略更改只作用于之后失败，已产生记录不追溯重写，提供确认清除全部健康记录。人工关闭永不被策略自动恢复。

持久健康记录新增 cause/reason 与可选 blocked动作，旧记录按 state 推断。关键点：分类和处置分离；5xx与普通403保持NEUTRAL；忽略动作不触发Key故障切换；不把“策略关闭”误报为空池。SettingsStore加载与update时同步策略，不能依赖打开UI才生效。错误归因仍为本次实际Key，禁止全局lastKey。

## 6 验收与交付
静态门禁+新增策略纯单元测试源码+Kotlin语法扫描+双语资源占位符；云端assembleRelease并跟进日志修复；下载arm64/universal/x86_64至/workspace，校验ZIP/sha256/签名块，不把构建通过当设备UI实测。非强制Git Data API提交，保留原签名和Firebase机制；更新唯一主文档详细说明实现、差异、迁移、策略语义、操作边界、测试与构建产物。
